# AI 中试基地高保真看板设计

## 目标与范围

本阶段把现有 Vite + React 原型重构为适合管理层汇报与日常经营查看的高保真交互看板。继续使用前端模拟数据，不引入登录、权限、后端服务或在线编辑。设计应完整覆盖看板总览、基础信息、经营信息、三大关键活动、政策/行业/产业动态，并在桌面、平板和移动端保持可用。

## 方案比较

### 方案 A：深色指挥中心

以深蓝大屏和发光图表为核心，汇报感染力强，但长时间阅读、复杂表格和移动端适配较弱。

### 方案 B：明亮经营驾驶舱（采用）

以明亮中性色为底，海军蓝导航建立专业感，华为红用于关键数字和状态强调。既有管理驾驶舱的信息层级，也适合日常浏览、筛选和下钻。

### 方案 C：极简数据工作台

以表格和筛选操作为核心，办公效率高，但总览的决策信息层级和展示效果不足。

## 信息架构

- 全局框架：可折叠式侧边导航、品牌区、当前年度和数据更新时间、用户身份区。
- 看板总览：页面标题和快捷动作、8 项 KPI、经营趋势与目标达成、基地地域分布、批复状态、重点基地排行、基地现状表。
- 基础信息：搜索与状态/行业筛选、基地卡片摘要、组织信息、建设规模、生态伙伴表，并可下钻经营信息。
- 经营信息：基地选择、收入完成度与剩余收入、算力结构、机会点、订货和收入产品拆分。
- 三大关键活动：顶部活动指标，场景矩阵、中试平台架构进度、生态活动时间线三个分区。
- 政策/行业动态：分类统计、分类筛选、资讯卡片、来源与发布日期。

## 视觉与交互

- 使用明亮经营驾驶舱方向：浅灰蓝背景、白色卡片、深蓝导航、红色关键强调，辅以青色、绿色和橙色数据语义色。
- 数字采用更强字重与紧凑字距；正文和表格保证中文可读性。
- 通过原生 CSS 绘制条形图、环形进度、趋势折线与算力堆叠条，避免为演示原型引入图表依赖。
- 所有筛选按钮提供明确的选中态；表格在窄屏横向滚动；侧栏在小屏变为顶部导航。
- 下钻继续使用当前组件状态导航，不引入路由依赖。基础信息和总览中的操作可直接定位对应基地的经营页。
- 交互控件使用语义化按钮、标签和表单，并保留键盘可访问性与焦点样式。

## 组件边界

- `App` 只管理页面导航和当前基地。
- `Nav` 管理全局品牌、菜单和辅助状态。
- 可复用 UI 组件承载页面标题、指标卡、状态标签、进度条、空状态和图表容器。
- 页面组件负责筛选状态和展示编排；聚合计算保持为纯函数，方便测试。
- 模拟数据扩展为足够支撑趋势、进度、场景参与方和资讯元数据的结构，但不模拟后端行为。

## 数据流与派生指标

模拟数据是唯一数据源。页面通过纯计算得到基地总数、批复率、标杆数量、建设金额、规划/实际/昇腾算力、预计与已完成收入、完成率和剩余收入。筛选仅影响当前页面展示，不修改源数据。收入剩余值以“年度预计收入减年度已完成收入”为准并下限归零。

## 异常与边界处理

- 找不到基地或经营记录时显示明确空状态。
- 除数安全处理，目标为零时完成率显示为零。
- 长单位名称、机会点和合作描述允许换行，不挤压关键数字。
- 日期按本地可读格式展示；模拟数据明确标注数据更新时间。

## 测试与验收

- 保留并更新页面导航和基地下钻组件测试。
- 增加筛选、经营派生指标和关键活动切换测试。
- 纯格式化与计算函数维持单元测试。
- 通过 TypeScript 构建、静态检查和 Vitest。
- 使用真实浏览器检查桌面与移动宽度，确认无关键内容溢出、控件可操作且视觉层级符合设计。

## 非目标

本阶段不实现真实 API、数据库、身份认证、权限、在线增删改、文件导入导出、实时资讯抓取或服务端部署。这些能力留待生产级全栈阶段。
